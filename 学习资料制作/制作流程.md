# 学习资料制作流程（新 HSK 四级词汇）

按论文第五章 5.3 节「学习材料」的方法，为四级词编写学习资料：词、字、搭配、例句、练习题、易混淆词。数据来源和文件夹说明见 [README.md](README.md)。

**怎么用这份文档**：每批词按第 1–8 步依次运行，第 9 步交作者审核。每一步写明论文依据、做法、命令、产出和**审核看什么**。和论文不一样的地方，集中写在最后的「与论文的差异」。

**分工**：取舍全部由程序按论文规则决定（哪个义项、哪句例句、哪两条搭配、哪些干扰项）；大模型只做需要语义判断的事（例句属于哪个义项、搭配是否成立、翻译、拼音校对、干扰项是否也说得通）；作者审核最终结果。

所有命令都在 `学习资料制作/` 目录下运行，`批` 写批次名，如 `第01批`。

---

## 总体安排

1. 每批约 10 个词，高、中、低频搭配着选，写进 `3_审核/<批>/词表.txt`（一行一个词，`#` 后是注释）。入选的易混淆词作为一个词加进同一批。
2. 第 01 批（11 个词）用来定流程和校准大模型，之后各批照做。第 02 批起由 `工具/plan_batches.py` 自动分批（见第 1 步）。
3. 四级词共 600 个（汉办词表里有四级条目的词）。

## 第 1 步　选词与分档（论文 5.3.1，附录 A、D、E、F）

```bash
.venv/bin/python 工具/step1_frequency.py
```

- **做法**：
  1. 附录 A：四级词的 BCC Global 词频，直接用作者整理的 Excel。**词的范围以汉办四级词表为准**：Excel 里混进了 22 个一至二级词（「了、不、到、着、好、会」等），排除；四级词「倍」不在 Excel 里，BCC 词频记 0。「了」原本排第 1，是规范化的最大值，排除后 54 个词换了档。
  2. 附录 D：教材课文清洗合并（附录 B、C），结巴分词（默认词典），统计词频。
  3. 附录 E、F：两列分别最小–最大规范化，总分 = 0.3 × BCC + 0.7 × 教材，降序排名。第 1–200 名高频，201–400 名中频，401 名以后低频（脚注 6）。
- **产出**：`2_加工结果/四级词加权词频分档.csv`（600 词）、`2_加工结果/HSK2012等级表.csv`（4995 词，后面各步查等级用）。
- **只需运行一次**；之后每批从分档表里选词。
- **分批**（第 02 批起）：先对还没做的词跑完第 2 步，再运行
  ```bash
  .venv/bin/python 工具/plan_batches.py          # 只打印计划
  .venv/bin/python 工具/plan_batches.py --write  # 写出各批 词表.txt，已有的批次不动
  ```
  跳过已在某批词表里的词和论文词库（`words_extended.db`）里已有材料的词。高、中、低频三档各自均匀摊到每一批，档内按加权排名，所以高频词先做；入选的易混淆词排在它的目标词后面，前面批次出现过的不再加（第 6 步出辨析题时会去那一批找它的例句）。
- **只做辨析**：论文词库里的词要参与辨析时（有入选易混淆词的四级词，如「发生 → 发现」；或是易混淆词，如「发现」），注释写「论文词库已有材料，只做辨析」。它照常走第 3–5 步，给辨析题提供例句和义项；第 6 步不做它的翻译检查，第 7 步不放进学习材料（审核清单开头列出）。
- **审核看什么**：选出的这批词高、中、低频是否搭配得当；虚词（如「与、而、以」）要不要做。

## 第 2 步　易混淆词（论文 5.3.1，附录 G）

```bash
.venv/bin/python 工具/step2_confusables.py 第01批
```

- **数据**：HSK 动态作文语料库，作者账号的登录令牌（`1_源数据/HSK动态作文语料库/登录令牌.txt`）。
- **做法**：
  1. 按网页「下载」的方式取回含目标词的标注语料：每个词两次请求（生成文件、取回文件），单线程，每次间隔至少 5 秒，出错立即停止、不重试。已下载过的词用本地文件，不再请求。
     - 网站回答「没有匹配到数据」的词，最后再补试（按语料库访问的规矩，连续几个都没有数据就停下）；仍然没有的，在下载目录里建一个空文件 `<词>.无数据`，按 0 句语料处理：没有易混淆词，学习材料照做。600 个词里有 12 个（千万、打折、现金、密码、航班、打印、干杯、弹钢琴、占线、放暑假、登机牌、填空），多是作文里很少写到的生活用语。
  2. 「检索原句」是改正后的句子，标注写作「正确的词{CC学习者写的词}」，如「继续{CC续继}」。筛出含「目标词{CC」的句子，每句只取第一处（同附录 G 的 `str.extract`），取出花括号里的词。
  3. 入选标准：目标词是四级词，偏误 ≥ 10 次，某个混淆词占 > 20%，且混淆词是**一至三级词**（论文：学习者已经学过），或是**另一个四级词**（作者 2026-10-29 加：两个词都在系统里学，各自学完再辨析，如「经历 → 经验」66%）。五级以上和词表外的不选（学习者还没学过）；写成目标词本身的（「而{CC而}」，标注造成）不算。
     - 入选与否每次读取时按现行规则用统计数字重新判定，不用 `易混淆词.csv` 里存的 `selected` 列，所以规则改过以后不必重新下载。
  4. 目标词另有一至三级条目的（600 个词里只有「得」「等」）不自动入选：语料不分义项，统计到的多是低级义项的偏误。例如「得 → 的」250 处全是「过得{CC的}很开心」这类二级结构助词，不是四级的助动词「得 děi」。报告开头注明；作者确定这类词不做辨析（2026-10-29）。
- **易混淆词的用途**：① 释义题的一个干扰项（有两个时取占比最高的；只用一至三级的，四级的易混淆词学习者可能还没学）；② 作为一个词单独学习（一至三级的；四级的本来就在自己那一批学），在 `词表.txt` 里加上，走第 3–7 步，内容来自教材和搭配库，**不用**语料库里学习者写的句子。语料库只用来确认易混淆词。
- **一至三级的易混淆词本身不跑第 2 步**（不需要再找它的易混淆词）：在 `词表.txt` 里它的行加注释 `# 易混淆词`，第 2 步会跳过。
- **产出**：
  - `2_加工结果/易混淆词.csv`：每个词列出全部混淆词、次数、占比、等级、是否入选。
  - `2_加工结果/易混淆词报告/<词>.md`：给人看，按混淆词分组，列出学习者写错的原句。
  - 下载的原始语料保存在 `1_源数据/HSK动态作文语料库/下载的语料/<词>.csv`，以后都用本地文件，不再请求网站。
- **方向**：「考虑{CC想}」表示**该用「考虑」的地方，学习者写成了「想」**，即论文引胡韧奋的「目标词误用为该词」。
- **审核看什么**：看报告里的原句，入选的是否确实容易混淆。
- **第 01 批结果**：只有「考虑 → 想」（31/74，42%，一级）入选。「原因 → 理由」占 28%，但「理由」是五级，不选。

## 第 3 步　候选清单（论文 5.3.2–5.3.4，附录 H、K、L、M、N）

```bash
.venv/bin/python 工具/step3_candidates.py 第01批
```

- **例句候选**：
  1. 教材课文按「。？！」切句（附录 H）。句首的杂质去掉再参选（作者 2026-10-29；论文词库的例句也有对话句）：
     - 对话的说话人「王静：」：只认课文里当说话人出现过至少 3 次的标签（47 个），「我决定：」这类句子内容不去；
     - 上一句落下的右引号「”」、题号「2黄色代表……」「2、」：属于句子的数字（「20世纪」「3天后」「8:00」「5公里」）不去。
     不去的话，这些句子被大模型当成片段判掉：406 个词少了一批可用候选，「出生」只剩一句 137 字的长句。
  2. 结巴分词后目标词是其中一个词才算（「想」在「理想」里不算）。默认词典切不出目标词时，临时加入分词词典再找，清单里注明。还找不到时，拆开粘在一起的「数词、指示词、程度副词 + 目标词」（一座、这场、很帅）和「目标词 + 方位词、补语」（桥上、留下、入口处）再找：量词「座」「场」「台」「棵」等原来一句都找不到。只在一句都找不到时才拆，不影响其他词。
     只学四级义项的「得」「等」取前 60 句（「等」的前 20 句全是 wait）。
  3. **补充例句**（作者 2026-10-30）：教材里一句可用例句都没有的词（12 个：师傅、签证、大使馆、勺子、理发、填空、百分之、推、篇、葡萄、凉快、预习），由大模型按论文的要求起草 5 句（10–25 字、除目标词外尽量只用一至三级词、覆盖常用义项），`工具/draft_examples.py`，产出在 `2_加工结果/补充例句/`。这些句子和教材句子一起作为候选，照常走第 4–8 步；审核清单里标明「例句由大模型编写」，请作者重点审。
  3. 词的复杂度 = 1 / log(BCC 词频)，再最小–最大规范化（附录 L）。句子复杂度 = 句中各词复杂度之和，查不到的词按 0（附录 M）。
  4. 按复杂度升序、再按句中四至六级词个数升序排，取前 20 句。
- **搭配候选**（附录 N）：先列分级阅读库，再列维基库；只要两个词组成、另一个词是一至三级的搭配，按互信息降序，各取前 20 条。
- **词典**：CC-CEDICT 里这个词和每个字的全部读音与义项。
- **产出**：`2_加工结果/候选清单/<批>/<词>.md`（给人看）、`<词>.json`（给后面的步骤用）。

## 第 4 步　语义判断（大模型，论文 5.3.3、5.3.4）

```bash
.venv/bin/python 工具/step4_semantic_tasks.py 第01批 --model deepseek-flash
```

- **大模型做什么**：
  1. 列出这个词面向中级学习者的义项（1–3 个，依据 CC-CEDICT，意思不同的不合并）。
     - 另有一至三级条目的「得」「等」只列四级条目的那一个义项：「得」是助动词 děi，「等」是表示列举的助词（汉办词表）。教材里多见的是低级义项（「过得很开心」的 de、「等一下」），按句数取义项会把它选成主义项。用别的意思的例句、搭配判为不可用。这条说明只加在这两个词的任务里（`HSK4_ENTRY`），其余词的任务不变。
  2. 每个候选例句里用的是哪个义项；残句、引文片段、标题粘连、录入错误、文言、讨论词语用法的句子判为不可用并说明原因。
  3. 每条候选搭配是否成立、属于哪个义项；偶然共现的组合（如「银行 估计」）、万能副词（也、都、还……）判为不成立。
  4. 词里每个字在这个词里的读音、词性、释义。
- **不加 `--model`** 只生成任务文件 `<词>.任务.json`，可由 Claude Code 在对话里作答。
- **产出**：`2_加工结果/判断/<批>/<词>.判断.<来源>.json`；用量记在 `用量.<来源>.jsonl`。
- **回答和任务对得上才用**：每份回答记下它对应的任务指纹（`_task`），并检查结构（每个例句、每条搭配都有回答，引用的义项存在，每个字都有释义）。重跑时，已有合格回答的词跳过；改了指令或候选清单后，旧回答自动作废、重新作答。回答不合格就停下，存为 `.不合格` 文件，不往下走。
- **采用哪一份**：把采用的那一份复制成 `<词>.判断.json`，第 5 步读它（同样核对指纹，对不上就报错）。
- **校准**（换模型或改指令时做）：同一批由两个来源各判断一次，运行
  `.venv/bin/python 工具/compare_judgments.py 第01批 claude-code deepseek-flash`，看 `对比.*.md`：最终选出的例句、搭配差在哪里，逐条判断哪里不一致。

## 第 5 步　按规则取舍（论文 5.3.2–5.3.5，附录 AD）

```bash
.venv/bin/python 工具/step5_select.py 第01批
```

全部由程序决定：

1. **义项**（5.3.3）：统计 20 句候选例句里各义项的句数。保留句数最多的义项；第二个义项句数 ≥ 2 且占可用例句 ≥ 30% 时也保留，最多 2 个。句数相同时，最简单的那句例句排在前面的义项优先，并加 ⚠ 提醒。舍去的义项和句数写进结果，审核时看得到。
2. **例句**（5.3.2）：每个保留的义项取复杂度最低的一句可用例句；有 30 字以内的可用例句时先从这些短句里取（作者 2026-10-29：例句要短，论文词库的例句中位数 16 字、最长 27 字）。填字题的句子同样短句优先。
3. **搭配**（5.3.4）：每个义项取成立的搭配里互信息最高的两条，先用分级阅读库，不够再用维基库；同一个搭配词不重复使用。两道搭配题：有两个义项时各取一条，再从剩下的搭配里补足。
4. **练习题**（5.3.5，附录 AD），格式同系统里现有的人工命题：

| 题型 | 题干 | 选项 |
|---|---|---|
| 释义题 | 主义项的英文释义 | 4 项：目标词 + 易混淆词（有的话）+ 一至三级随机词 |
| 搭配题（2 道） | 选出的搭配，目标词换成括号，如「认真 ( )」 | 4 项：目标词 + 3 个一至三级随机词 |
| 填字题 | 主义项的例句本身（学习页上那句；论文 3.2 节「句子来自于学习模块的例句」，作者 2026-10-30），挖掉目标词的最后一个字；例句里目标词出现不止一次时用同一义项的下一句 | 不设选项；学习者手写作答 |

随机词排除目标词、易混淆词和与目标词有相同汉字的词；以词本身为随机种子，重复运行结果不变。每道选择题另抽 8 个**备用干扰项**，第 6 步一起检查。

填字题按分词结果定位：目标词必须作为完整的词、且只出现一次，否则换下一句。这样「理想」里的「想」不会被挖掉，句子里另一处目标词也不会泄露答案。

- **产出**：`2_加工结果/取舍/<批>/<词>.json`。屏幕上逐词显示保留与舍去的义项，⚠ 标出例句或搭配不够的情况。

## 第 6 步　翻译与检查（大模型，论文 5.3.5）

```bash
.venv/bin/python 工具/step6_check_tasks.py 第01批 --model deepseek-flash
```

- **先截短长句**（作者 2026-10-29）：例句和填字题的句子超过 30 字的（教材是中级的，句子长，117 个义项里 99 个找不到短的可用句），交给大模型截出含目标词、能独立成句的一段。截出的必须是原句里按标点断开的连续一段，只删前后的分句，不改字、不删中间的字，由程序核对；截错的或截不出的保留原句。截短写回第 5 步的取舍结果（原句记在 `original`），后面的翻译、拼音、练习题和第 7、8 步都用截短后的句子；审核清单里标出「例句截自原句：……」。任务 `<词>-截短.任务.json`，回答 `<词>-截短.截短.<来源>.json`。

- **大模型做什么**：
  1. 词的拼音。
  2. 例句的英文翻译；例句拼音先由 pypinyin 逐词自动标注，再由大模型改错，主要是轻声和多音字。
  3. 搭配的英文翻译。
  4. 选择题的干扰项和备用干扰项里，哪些也说得通（会造成两个正确答案）。
  5. 填字题的括号里还能填哪些字。
  6. **易混淆词辨析**（论文 2.2.4、3.2.4、6.5）：这一批有要做的易混淆词对时，单独一个任务 `<目标词>-<易混淆词>.任务.json`，回答存为 `.辨析.<来源>.json`，采用的复制成 `.辨析.json`。
     - 一对放在两个词里**靠后出现的那一批**做（四级词之间的词对，两个词在不同批次），那时两个词第 3–5 步的产出都有了；每个词的产出都取它所在那一批的，缺了就报错。
     - 两个方向都入选的（「经历 → 经验」「经验 → 经历」）是同一对，只做一次：保留写错次数多的方向，另一个方向的统计也写进讲解。
     - `素材.json` 的词对带 `word2_level`（易混淆词等级）：为 4 时，系统要两个词都学习期复习完才带出辨析。
     内容包括：
     - **混淆点**：把学习者写错的原句（最多 15 句）交给大模型，归纳学习者实际错在哪。这些原句只供分析，不进入学习内容（作者同意，2026-10-29）。这是论文 6.5 节引张博的建议：「对准混淆点」。
     - **讲解用英文**：学习者是中级水平，中文讲解里的「状语」「小句」这类说法比要辨析的词还难；论文也主张用翻译法辅助学习、适度引入汉外对比（6.5 节引张博）。中文只出现在例句、搭配和词本身里，词第一次出现时写成「汉字 拼音」。
     - 为什么容易混、区别（第一行是两个词各自的英文意思）、**搭配对比**（附英文意思）、记忆提示、难度。
     - **对错例句**：✓ 句附英文翻译，必须是换成另一个词就不对或意思变了的；✗ 句写成「错句 → 正句 (英文翻译) 英文原因」，至少两句 ✗ 要对准混淆点。
     - **辨析题**：两个词各自可用的例句里，目标词作为完整的词只出现一次的，整词挖空，每个词最多 6 道候选；大模型逐句检查另一个词能不能填、句子是否适合出题，并给每题写一句英文解释（学习者答完后看）。
- **产出**：`2_加工结果/检查/<批>/<词>.检查.<来源>.json`，任务指纹和结构检查同第 4 步：例句、搭配都要有翻译；拼音里的字拼起来要和原句一致；每道选择题都要给冲突列表。把采用的那一份复制成 `<词>.检查.json`。

### 第 6b 步　填字题改用学习页上的例句（2026-10-30 补改已做好的批次）

此前填字题用的是主义项的**第二句**例句，学习者在例句页上没见过那句，有的句子里别的字比答案自然得多（「我不明白，为什么 ( d ) 有人叫我“奶奶”？」答案「得」，「会」「总」更顺，连母语者都要猜）。现在第 5 步改为先用例句本身；已经做好、审核过的批次用 `工具/step6b_fill_from_example.py <批> --model deepseek-flash --apply` 补改：

- 用主义项的例句（第 6 步截短之后、学习页上显示的那句）重新挖空，规则同第 5 步；例句里目标词不是只出现一次的完整词时保留原题。
- 句子换了的，只问大模型一个问题：括号里还能填哪些字、答案字的拼音（任务 `<词>-填字.任务.json`，回答 `<词>-填字.填字.<来源>.json`），据此按论文给声母或拼音提示。不重做第 6 步的整体检查，翻译、干扰项都不变。
- `--apply` 只替换 `data/learning_materials/hsk4/<批>.json` 和 `3_审核/<批>/素材.json` 里的那道填字题，别的内容一个字不动（整批重新生成会带出第 1 批上线后规则改动造成的别处差异）；改动列进 `3_审核/<批>/填字题改用例句.md`。第 7 步重新生成时也优先用这里的检查结果。
- 2026-10-30 跑完 56 批：580 道填字题里 503 道改用例句，77 道不变（本来就是例句，或例句里没法挖空）。
- **作者审核后的个别题**写在 `step6b_fill_from_example.py` 的 `OVERRIDES` 里，重跑不会被冲掉：`previous` 保留原来的题（这一步不再改它；素材里已是例句题的，`--apply` 时换回原题），给一句句子的用那句出题（同样要问一次大模型）。2026-10-31 预审后：各、印象保留原题，页改用候选清单里的一句（见 `.review/填字题预审-可疑题.md`）。
- **提示的声母**：界面上写的是「拼音以 z 开头」，所以别的能填的字声母以答案的声母开头（z / zh、c / ch、s / sh）也算区分不开，给完整拼音（`step7_build.fill_hint`）。
- **另一种也对的写法**（同音、意思也对，换什么句子都躲不开，如「师傅 / 师父」）写在 `step7_build.ALSO_CORRECT`，放进填字题的 `options`，判分时也算对（填字题本来不用 `options`）。

## 第 7 步　汇总

```bash
.venv/bin/python 工具/step7_build.py 第01批
```

- 第 6 步判定也说得通的干扰项，换成第 6 步检查过、说不通的备用干扰项（论文 5.3.5：重新选择，直到其他选项不能作为正确答案）。备用词用完仍有冲突的，清单里标明需要人工处理。释义题里的易混淆词**不替换**：论文有意把它设为一个选项（2.1 节）。
- 搭配的互信息为负（两个词一起出现得比偶然还少）时，清单里加 ⚠ 提醒确认是否常用。这种搭配是因为互信息更高的候选都被判为不成搭配才轮到的。
- 最后核对每道选择题：4 个选项互不相同，正确答案恰好出现一次。
- 填字题括号里还能填别的字时，给出被挖掉那个字的拼音作提示。
- **产出**：
  - `3_审核/<批>/素材.json`：字段同系统现有的补充材料，例句拼音格式如「我/wǒ 认为/rènwéi ……」，搭配格式如「认真（三级） 考虑」；另加 `senses`（按义项分组的例句和搭配）和 `exercises`。
  - `素材.json` 里的 `confusable_pairs`：易混淆词辨析内容，字段同系统的 `confusable_pairs` 表。「为什么容易混」后面由程序补上语料库的统计数字和混淆点；「区别」后面补上搭配对比和英文对比。
  - 辨析题（`questions`）：每个词取 2 道另一个词填不进去、又适合出题的，候选按复杂度从低到高；两个选项是这两个词，顺序随机（论文 3.2.4）。
  - `3_审核/<批>/审核清单.md`：逐词列出全部结果和取舍依据，最后是易混淆词辨析。

## 第 8 步　发音音频（论文 5.3，附录 O）

```bash
.venv/bin/python 工具/step8_audio.py 第01批
.venv/bin/python 工具/step8_audio.py --thesis   # 论文词库（words_extended.db）里已有材料的词，一次即可
```

- **做法**：给整词、每个字、每条搭配、每条例句各生成一个 mp3。论文用百度翻译网页的朗读接口（附录 O），那是网页内部接口；这里改用 **Azure 语音服务**的正式接口（`工具/tts.py`）：
  - 声音 `zh-CN-XiaoxiaoNeural`（晓晓），语速慢 10%（作者试听四个声音、两种语速后选定）。
  - 多音字按校对过的拼音指定读音（SSML phoneme，如「得」→ `dei 3`）。只在拼音和 pypinyin 默认读法不同时才标：标注会让引擎完全照标的读，「一」「不」的变调就由不得它了，所以「一」「不」和儿化的「儿」不标。
  - 搭配去掉等级标注再读（「认真（三级） 考虑」→「认真考虑」），只给其中的目标词标注；例句按第 6 步的分词拼音对齐，对话开头的说话人（「李进：」）不读。
  - 文件名是内容指纹：内容不变就不重新生成、不重复花额度；第 7 步重跑以后再跑这一步，只补变了的。
- **Key 与额度**：Key 放 `工具/azure_speech_key.txt`（第一行 Key，第二行区域 `eastus`），不提交。免费档（F0）每月 50 万字符（一个汉字计 2 个字符，SSML 标签也计费），每分钟最多 20 次请求；额度用完只拒绝、不收费。第 02 批起一次做完全部批次，作者把资源改为按量付费（S0，每秒 200 次，按字符计费，全部约 2–3 美元），运行时加 `AZURE_TTS_INTERVAL=0` 去掉请求间隔、几批同时跑（不加时按免费档每 3.2 秒一次）。第 01 批 67 个音频约 2,800 字符；每次运行先打印这一轮要新增的字符数。出错直接停止、不重试，已生成的保留。
- **产出**：
  - `data/learning_materials/audio/<指纹>.mp3`（仓库里，不提交，部署时复制到服务器）。
  - 音频地址（`/api/audio/<指纹>.mp3`）写回 `素材.json` 的整词、字、搭配、例句；`--thesis` 写成清单 `data/learning_materials/audio/论文词库.json`，后端启动时由 `scripts/apply_audio_manifest.py` 补进库里（只填空着的或早期的占位地址）。
  - `3_审核/<批>/试听.html`（`--thesis` 是 `3_审核/论文词库试听.html`）：逐词列出字、词、搭配、例句和播放按钮。
- **审核看什么**：在试听页里听，重点是多音字、单字的声调、轻声。读错的，改正拼音后重跑这一步。

## 第 9 步　作者审核与导入

1. 作者看 `审核清单.md`，逐词核对：
   - 义项是否恰当；
   - 例句是否适合学习者；
   - 翻译、拼音是否准确；

### 系统里的辨析（论文 2.2.4、3.2.4）

## 大模型与费用

- 用 DeepSeek `deepseek-flash`（思考模式默认开启）。API Key 放 `工具/deepseek_api_key.txt`，不提交。教材例句片段会发送到 DeepSeek 的服务器。

- **费用实测**：第 4 步每个词约 1,500 token 输入、约 8,000 token 输出（大部分是思考），第 01 批 11 个词约 ¥0.8。第 4、6 步合计，600 个词估计高峰时段约 ¥85，错峰时段约一半。据第三方汇总，高峰是工作日北京时间 09:00–12:00 和 14:00–18:00，其余时段半价，以 DeepSeek 后台为准。
- 出错直接停止、不自动重试，免得重复扣费；已有回答的词不会重复调用。
