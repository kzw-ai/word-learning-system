# 移动端 App（iOS / Android）实施方案

> 状态：**方案已由作者审阅通过，按审阅意见修订（v2）**。本文档只做方案记录；实施从第 2 步开始。
> 分支：`feat/mobile-app`。工作目录：`~/Desktop/word-app`。

---

## 0. 结论（TL;DR）

用 **Capacitor** 把现有 Next.js 前端打包成 iOS + Android 原生壳，一套代码同时出两个平台；后端继续用现有 Flask 服务，App 只承担「界面 + 学习流程」，所有数据与学习记录仍走后端。

要动的核心是：

1. **身份**（最重要）：把所有带身份需求的请求统一走「请求头身份」（`X-Session-Token` / `X-Guest-Id`），不再依赖 cookie；并把 token / 访客 ID 再备份一份到 Capacitor Preferences。
2. **相对地址 + 静态导出**：`next build` 增一条「静态导出」构建路径，App 内所有 API / 音频都拼成后端绝对地址。
3. **Capacitor 工程**：新增 `ios/`、`android/` 原生壳，接 Preferences、Keyboard 两个插件。
4. **后端 CORS**：收紧为白名单来源 + 预检缓存（单独提交，部署由作者做）。
5. **上架必需**：删除账号（后端接口 + 前端入口）、隐私政策页面。

## 1. 技术选型与理由

### 1.1 选型：Capacitor（当前最新稳定大版本）+ Next.js 15 静态导出

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Capacitor + 静态导出** | ✅ 采用 | 复用现有全屏手机页面（`h-[100dvh]`、`max-w-[430px]`、`env(safe-area-inset-*)` 均已就位）；一套代码同时出 iOS/Android；后端继续用 Flask |
| React Native / Flutter 重写 | ❌ | 要把 6 个学习页面 + 练习 + 手写/笔顺动画全部重写成两套原生，工作量大、易与网页版走样 |
| Tauri | ❌ | 不支持 iOS |
| 纯 PWA 上架 | ❌ | 无法进 App Store，iOS 上 cookie/身份问题依旧，且不能加本地通知等原生能力 |

前端用 Next.js **pages 路由 + `output: 'export'` 静态导出**，产物打进 Capacitor 的 `webDir`。静态导出不支持 `rewrites`/`redirects`，因此 App 构建路径下这两项要条件化去掉（详见 §3.2），对网页版（`npm run build && npm start`）零影响。

### 1.2 Capacitor 版本与依赖原则

- **不用 Capacitor 6**：太旧。用 npm 上**当前最新稳定大版本**并把所有 `@capacitor/*` 依赖写死到同一版本（不写 `^`）。
- **安卓 `targetSdk`**：实施时确认生成的 Android 工程 `targetSdkVersion` 满足 **Google Play 当前要求**（不足则显式升到要求值），避免提交审核被打回。
- 项目内 npm 依赖版本写死（工作规矩第 5 条）。

## 2. 现状梳理（读码结论）

### 2.1 身份机制（后端）

- 后端只认两种身份凭证（`user_data_isolation.py` 的 `get_current_user_from_request()`）：
  1. 登录用户 session token：请求头 `X-Session-Token` 或 cookie `session_token`；
  2. 未登录访客 guest id：请求头 `X-Guest-Id` 或 cookie `guest_id`（格式 `guest_` + 16–64 位字母数字，见 `src/lib/guestIdentity.ts`）。
- URL / query / body 里的 `user_id` **不是**身份（除非 `ALLOW_USER_ID_PARAM=1`，本项目绝不开）。
- **注册时**后端会调用 `get_guest_id()` 把访客数据合并进新账号（`app_phase.py` 的 `register()` → `merge_guest_into_user()`）。App 里 cookie 带不过去，所以注册请求**必须显式带 `X-Guest-Id`**。

### 2.2 前端已有但未普及的身份设施

- `src/lib/authClient.ts` 的 `authenticatedFetch` 已经会带 `X-Session-Token` / `X-Guest-Id` 头（存 localStorage）。
- `src/lib/apiClient.ts` 的 `fetchWordExercises` 也自己带了头（注释说明了「循环依赖」问题）。
- 但 `pages/`、`src/context/`、`src/hooks/` 里还有一批**直接 `fetch(buildApiUrl(...))` 不带任何身份头**的调用，靠同源 cookie 认人；打包成 App 后（页面来源是 `capacitor://localhost` / `https://localhost`，与后端不同源）这些请求会全部被当成「无身份」，学习记录会丢。

- `buildApiUrl()` 前缀由 `NEXT_PUBLIC_API_BASE_URL` 决定（`src/lib/apiClient.ts`）。

- `/hanzi-data/*.json` 在 `public/`，随 App 打包，不改（`prebuild` 脚本 `scripts/copy_hanzi_data.js` 已复制）。

### 2.5 后端 CORS 现状

### 2.6 其他现状

- PWA：`public/manifest.json` + `src/lib/serviceWorker.ts`；App 里不需要注册 SW（`pages/_app.tsx` 16–29 行）。
- `pages/_document.tsx` 29 行 viewport 已含 `viewport-fit=cover` + `interactive-widget=resizes-content`。
- 练习页打字题在 `pages/exercise.tsx`（fill-word 的 type 模式），需保证键盘不遮输入框。
- 音频播放已是「点按触发」；iOS 静音键 / 锁屏行为需在模拟器确认。
- 已有移动端走查脚本：`tests/mobile/{walk.py,audit.py,level.py,run_all.sh,drivers.py}`，设备名 `WL iPhone SE`、`iPhone 17 Pro Max`、`wl_pixel7`。

## 3. 前端改造方案

### 3.1 统一身份请求头（最重要）

**问题**：`authClient` 依赖 `apiClient`（`buildApiUrl`），`apiClient` 里的 `fetchWordExercises` 想带身份头却不能反向 import `authClient`（循环依赖）。解决：把「取身份头」抽成独立模块。

**改动**：

1. **新增 `src/lib/authHeaders.ts`**（无依赖、纯函数）：
   - `getSessionToken()`：读 localStorage `session_token`，容错。
   - `getGuestId()`：复用 `guestIdentity.storedGuestId()`。
   - `getAuthHeaders(): Record<string, string>`：有 token → `{ 'X-Session-Token': token }`；否则有 guest id → `{ 'X-Guest-Id': id }`。

2. **`src/lib/authClient.ts`**：`authenticatedFetch` 改为用 `getAuthHeaders()` 拼头（仍走 `buildApiUrl`、`credentials:'include'`），行为不变。

3. **`src/lib/apiClient.ts`**：`fetchJson` 默认把 `getAuthHeaders()` 合入请求头（公开接口带上无害，用户接口带上正确）；`fetchWordExercises` 里的手写头逻辑改为复用 `getAuthHeaders()`。

4. **逐处替换** §2.3 A 表里所有 `fetch(buildApiUrl(...))` → `authenticatedFetch(...)`（保留各自 `method`/`body`/`cache` 选项）：
   - 注册：`authenticatedFetch` 自动带 `X-Guest-Id`（无 token）→ 满足后端合并需求。
   - 登录：走 `authenticatedFetch` 无害；登录成功把 `session_token / user_id / username` 写 localStorage **并写 Preferences**（§3.4）。
   - 退出 / 校验：走 `authenticatedFetch`，自动带 `X-Session-Token`。

5. **`utils/timeTracker.ts`** 404 行 batch 事件：改为带 `getAuthHeaders()`。

6. **`src/hooks/useAuth.ts` / `components/ProtectedRoute.tsx`**：作者明确「不动，不在本次范围」。

### 3.2 静态导出 + 相对地址

1. **`next.config.js` 条件化**（只在 `NEXT_OUTPUT=export` 时启用导出相关项）：
   - `output: 'export'`（网页版保持默认 server 构建）。
   - `trailingSlash: true`（导出时加，避免 App 内刷新深链页回到首页）。
   - `images: { unoptimized: true }`（静态导出要求；本项目未用 `next/image`，纯保险）。
   - `redirects` / `rewrites`：导出构建时返回空数组，网页版保留。

2. **新增 npm script**（`package.json`）：
   - `"build:app": "NEXT_PUBLIC_API_BASE_URL=https://learnchinese.kzwbelieve.top NEXT_OUTPUT=export npm run build"`
   - `"sync:app": "npm run build:app && npx cap sync"`
   - 本地调试另用一条指向 `http://127.0.0.1:5004` 的脚本（见 §7 本地调试说明）。

3. **音频补前缀**：`components/AudioPlayer.tsx` 137 行 `new Audio(audioUrl)` → `new Audio(buildApiUrl(audioUrl))`（对绝对地址原样返回，对 `/api/audio/...` 补前缀）。`audioUrl` 为空分支已有判断，不受影响。

### 3.3 Service Worker（App 里不注册）

`pages/_app.tsx` 的 `registerServiceWorker` 调用处加判断：`import { Capacitor } from '@capacitor/core'`，`if (!Capacitor.isNativePlatform()) registerServiceWorker(...)`。网页版行为不变。

### 3.4 Capacitor Preferences 备份（防 iOS 清 localStorage）

**改动**：新增 `src/lib/appStorage.ts`，封装「关键键同时写 localStorage 与 Preferences」，启动时回填。

- 备份键：`session_token`、`user_id`、`username`、`learningSystem.guestId`。
- `restoreAuthFromPreferences()`：仅 `Capacitor.isNativePlatform()` 时，从 `@capacitor/preferences` 读，对 localStorage 缺失键回填。
- 写入点：登录成功（`pages/login.tsx`）、登出清除（`useAuth.logout` 不改则跳过）、访客 ID 生成（`guestIdentity.ensureGuestId`，fire-and-forget）。
- **时序**：`LearningContext` 挂载 effect 里先 `await restoreAuthFromPreferences()`，再 `setUserIdState(readInitialUserId())`。

## 5. 后端 CORS 收紧（单独提交）

`app_phase.py` 60 行改为白名单 + 预检缓存。**不写死 `allow_headers`**（flask-cors 默认 `'*'` 全放行）：

```python
CORS(
    app,
    supports_credentials=True,
    resources={r"/*": {"origins": [
        "https://learnchinese.kzwbelieve.top",   # 线上网站
        "capacitor://localhost",                  # iOS App
        "https://localhost",                      # 安卓 App
        # 本地调试来源（作者同意加入）：
        "http://localhost:3100",
        "http://127.0.0.1:3100",
    ]}},
    max_age=86400,  # 预检结果缓存一天：带身份头后跨域每个请求都先发 OPTIONS，缓存省一次往返
)
```

要点：
- `supports_credentials=True` 时**不能**用 `*`，必须列明确切来源。
- `max_age=86400` 让浏览器/WebView 缓存预检结果一天，避免 App 里每个请求都多一次 OPTIONS 往返。
- **单独一个提交**；部署由作者完成，本步骤不部署、不连生产。

## 6. 上架必需功能

### 6.1 删除账号（后端 + 前端）

苹果与 Google Play 都要求 App 内可删除账号。项目现在没有此功能，需新增：

**后端**（单独提交）：
- 新增接口（建议 `DELETE /api/auth/account` 或 `POST /api/auth/account/delete`）：
  - 仅登录用户可调用（读 `X-Session-Token` / cookie，`validate_session` 得 `user_id`；访客无账号，不适用）。
  - 删除该用户**全部**数据：账号行 + 学习会话、作答、进度、推荐、易混淆词进度、分析事件等所有以 `user_id` 归属的记录（实施时按数据库实际表清单逐表确认，`merge_guest_into_user` 的表名可作参照）。
  - 失效其 session token。
  - 返回成功/失败。
- **新增 pytest 测试**：注册用户 → 产生学习数据 → 删除账号 → 断言账号与学习记录均被清空、旧 token 失效。

**前端**（App 入口 + 二次确认）：
- 在登录页（账号动作所在处）加「Delete my account」入口，二次确认（确认框 + 明确警示「连同学习记录一起删除、不可恢复」），确认后调删除接口，成功后清除本地登录态回到首页。

### 6.2 隐私政策页面

两个商店提交都要填隐私政策网址。新增页面 `/privacy`（Next.js 页面），**先放占位内容**（标题 + 说明「正文由作者提供」），随 App 与网页版一起构建；正式文案由作者后续补齐。
