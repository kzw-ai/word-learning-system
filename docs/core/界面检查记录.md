# 界面检查记录

记录每个页面、每种状态在哪些手机上按什么标准检查过、结论是什么，避免重复审核。

## 怎么用

1. **改了界面，先查这份记录**：找到受影响的页面，看「代码版本」一栏。
2. **判断要不要重审**：`git log <代码版本>.. -- <这页的文件>` 没有输出，说明那之后这页没改过，沿用记录的结论；有输出就重审。共用组件（`components/learning/`、`styles/`、`tailwind.config.js`）改了，用到它的页面都要重审。
3. **记录里没有的页面或状态**，以及下面「没覆盖到的」那些项，照常判断，不能当成已经查过。
4. **审完更新这份记录**：结论、发现的问题和修复提交、新的代码版本。

跑检查：`tests/mobile/run_all.sh audit`（三台模拟器同时，约 5 分钟）。截图、每台的结果和汇总报告在 `.review/layout/`（不提交）。前置准备见 [测试文档.md](测试文档.md)「手机兼容性测试」。只想快速看样式时，可以先用桌面 Chrome 调成手机尺寸截图（可见高度：SE 375×549、Pro Max 440×796、Pixel 7 412×783），最后再上模拟器确认。

## 评审标准

### 脚本自动量的（`tests/mobile/audit.py`）

| 编号 | 检查项 | 标准 |
|------|--------|------|
| L1 | 一屏放得下 | 主要内容在 iPhone SE（Safari 可见高 549px）上不用滚动就看得到；放不下的区域要能滚，并有「下面还有」的提示（底部滚动阴影或吸底工具栏的阴影） |
| L2 | 横向溢出、出屏、截断 | 页面不能横向滚动；文字不能超出屏幕或被截断 |
| L3 | 字号 | 正文不小于 14px |
| L4 | 点按目标 | 按钮、链接、输入框高宽不小于 36px（文字链接用 `py-2` 加高点按区域） |
| L5 | 被盖住 | 静止时文字不被别的元素盖住（遮罩弹窗、滚到底栏下面的可滚内容除外） |
| A1 | 对比度 | WCAG AA：正文 4.5、大字（≥24px 或 ≥18.66px 粗体）3；禁用控件和 `aria-hidden` 的装饰不算 |
| A2 | 留白平衡 | 内容块之间的空白不超过屏高的 15%；吸底工具栏上方的空档单独记为「工具栏空档」，不算失衡 |
| A3 | 对齐 | 屏幕左侧起头的正文，左边缘不能差 1–6px |
| A4 | 字号、颜色种数 | 一屏字号不超过 5 种，文字颜色不超过 6 种 |
| A5 | 主按钮 | 一屏只有一个抢眼的主按钮（禁用的不算） |

### 要人看的（截图逐张看，参考 Argon 评审和设计原则）

| 编号 | 检查项 |
|------|--------|
| V1 | 主角清楚：这一页要学习者看的东西（要自评的词、题干、词头）是最大最醒目的，不被标题、说明、导航抢走 |
| V2 | 风格统一：顶栏、主按钮、卡片、选项、反馈都用下面「设计规范」里的同一套样式 |
| V3 | 卡片按角色用：只给需要突出的块加卡片，不处处套毛玻璃 |
| V4 | 不用 emoji 当标记或插图；避免紫蓝渐变满屏、处处居中、处处大圆角这类「AI 生成感」套路 |
| V5 | 配色：靛蓝紫做主色，slate 灰做中性色，绿 / 红只表示对 / 错；背景不偏粉 |
| V6 | 数量和状态一眼看得出：比如自评有几个选项（带 1–5 序号）、下面还有没有内容 |

## 设计规范（现在在用的）

| 用途 | 写法 |
|------|------|
| 背景 | `modern-gradient-bg`：`from-slate-50 via-indigo-50/40 to-slate-100` |
| 外层面板 | `glass-panel`：`bg-white/90` 加 `border-indigo-100/80`，淡靛蓝阴影 |
| 卡片、选项 | `glass-card`：实心白底加 `border-slate-200/80` |
| 主按钮 | `h-12`（自评页 `h-14 short:h-12`）`rounded-2xl bg-gradient-to-r from-indigo-600 to-violet-600`，禁用 `from-slate-200 to-slate-200 text-slate-500` |
| 顶栏按钮 | `h-9 px-3 rounded-xl bg-white/80 border border-slate-200/70 shadow-sm text-indigo-700 text-sm font-semibold`；标题 `text-xl font-extrabold text-slate-900` |
| 选项 | 默认白底细边框；选中 `bg-indigo-50 border-indigo-500 ring-1 ring-indigo-500/20` |
| 反馈 | 答对 `bg-emerald-50 border-emerald-200`、按钮 `bg-emerald-700`；答错 `bg-rose-50 border-rose-200`、按钮 `bg-rose-600` |
| 吸底工具栏 | `bg-slate-100/95 border-t border-slate-200/70` 加向上的淡阴影 |
| 能滚的区域 | `scroll-fade`：下面还有内容时底部出现阴影 |
| 文字颜色 | 标题 `slate-900`，正文 `slate-700`，次要说明 `slate-600`（浅底上不用 `gray-400/500`） |
| 屏幕高度断点 | `short` ≤ 700px（紧凑排版）、`roomy` ≥ 760px（手写框加大到 280）、`tall` ≥ 860px（自评页显示学习统计栏） |

## 例外和没覆盖到的

- **`/learning-stats`**：开发者页面，生产环境首页不给入口，字号和对比度不达标，不在学习者路径上，没改。
- **`/phase-demo`、`/system-status`、`/time-tracking-demo`**：开发演示页，没查。
- **iOS 软键盘**：iOS 模拟器默认连着电脑键盘，点输入框不弹软键盘，「键盘弹起挡住输入框」在 iOS 上没测到。
- **安卓键盘**：模拟器的输入法因为之前模拟过手写，处在手写笔模式，点输入框弹出的是手写工具条而不是键盘；键盘弹起的版面在安卓上也没测到。
- **没走到的状态**：易混淆词辨析页（「得」没有辨析对）、今日复习有到期词、「全部学完」、四字以上的长词、横屏。
